# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Set up the CI/CD infrastructure for the project. The CI pipeline runs on every pull request and push to main, checking formatting with `cargo fmt`, linting with `cargo clippy`, running the test suite, validating against the minimum supported Rust version (1.85.0), and auditing dependencies for license compliance and known vulnerabilities via `cargo-deny`. Every pull request is also required to include a changelog entry. A separate release workflow, triggered manually, validates the version, publishes the crate to crates.io, and creates a GitHub Release with the changelog section as release notes. [PR #1](https://github.com/fedonman/sqwatch/pull/1)

### Changed

- Overhauled the filter pane and titlebar layout. The titlebar is now split into four distinct sections: brand, logged-in user, active filters, and a dedicated flash notification bar that takes the remaining space. Filter and column settings are now persisted to disk (`~/.config/sqwatch/`) and restored on launch. The user filter was changed from exact match to regex-based matching, and node filtering was converted from a free-text regex field to a selectable list populated from `sinfo`. The squeue query now passes `--all` and `--states=all` by default so that all job states are displayed, including newly recognized states `SUSPENDED` and `OUT_OF_MEMORY`. Job cancellation via `scancel` now properly checks exit status and reports errors through the flash bar instead of silently discarding failures. Job selection and cursor position are preserved across the 1-second auto-refresh cycle by remapping via job ID. The statusbar was reorganized with keybinding hints on the left and right-aligned job statistics, and several keybindings were updated: script inspection moved from `Enter` to `s`, the `q` close binding was removed from overlay panes in favor of `Esc`, and `PageUp`/`PageDown`/`Ctrl+U`/`Ctrl+D` were removed from the script pane. Column headers no longer change color when used for sorting. [PR #2](https://github.com/fedonman/sqwatch/pull/2)

- Redesigned the application layout from an overlay-based model to a configurable split-pane architecture. The previous `output_pane` module, which combined stdout and stderr into a single pane with tab switching, and the `search` module, which rendered filters as a modal popup dialog, were both removed. In their place, stdout and stderr are now independent inline widgets that divide the right panel vertically, the filter system was rebuilt as a persistent sidebar with regex-validated text inputs for username and job name along with selectable checkbox lists for states, nodes, partitions, and QoS, and a new widget selector dialog (toggled with `w`) lets users show or hide each panel independently. The script pane was renamed from `script_pane` to `script_widget` to reflect its role as a first-class layout component rather than an overlay. Layout visibility preferences are persisted to `~/.config/sqwatch/layout.json` alongside the existing filter and column configuration files. The titlebar was simplified to show the brand, a flash notification area, and the logged-in username, while the statusbar now renders context-sensitive keybinding hints on the left with job statistics on the right. Focus cycling via `Tab` and `Shift+Tab` traverses only the currently visible widgets, and `Shift+Up`/`Shift+Down` navigates the job table from any right-side widget without switching focus. The project license was changed from MIT to Apache-2.0 and the README was expanded with an architecture overview, developer guide, and updated keybinding reference. A broad pass was made to align the codebase with Rust 2024 edition idioms: the ANSI escape regex used for `bat` syntax highlighting is now compiled once via `LazyLock` instead of on every render frame, `color_eyre::install()` is called at startup to enable enhanced error reports, the `Ordering` enum was renamed to `SortDirection` to avoid shadowing `std::cmp::Ordering`, the `HashMap` backing squeue sort parameters was replaced with a `Vec` to guarantee deterministic field ordering across runs, all string truncation was rewritten to operate on `char` boundaries rather than byte offsets to prevent panics on multi-byte UTF-8 input, and the `everything_marked()` predicate was corrected to return `false` when the job list is empty instead of vacuously returning `true`. Duplicated code was consolidated throughout: the identical `scontrol show job` invocations and key-value parsers that existed separately in both the output and script widgets were extracted into a shared `scontrol_show_job()` function returning a typed `JobDetail` struct, the near-identical regex filter blocks for user and job name in the dashboard were unified into a single `apply_regex_filter()` helper, the three identical `Shift+Up`/`Shift+Down` key handlers were merged into one `on_widget_key()` dispatch method, the repeated XDG config directory resolution was extracted into a shared `sqwatch_config_dir()` function, and color constants that were duplicated across four view modules were centralized into a new `views/theme.rs` module. All dead code was removed, including the unused `_shorten`, `_human_memory`, `_human_duration`, `_run_squeue`, `_run_scontrol`, `_update_job`, and `_set_refresh_rate` functions that had been suppressed with underscore prefixes, and the `_tx` and `_worker` fields on `InputLoop` were documented to clarify why they are retained for channel and thread lifetime management. [PR #3](https://github.com/fedonman/sqwatch/pull/3)
